The two objects you will use throughout this lab
On the server side, you create an MCPServer and decorate Python functions with @mcp.tool(). You start it with mcp.run() — that is where you pass the transport (stdio by default, or SSE / Streamable HTTP with a port).
On the client side, you use a single Client object. Pass it a transport, enter async with, then call list_tools() and call_tool(). The connection is ready as soon as you enter the context manager. Official reference: Client transports.

Step 1: Introduction to MCP

MCP (Model Context Protocol) is how a language model talks to tools you write. You expose ordinary Python functions. The model can then call those functions to query a database, read a file, or talk to GitHub — instead of guessing.

Think of an MCP server as a small program that says: “Here are the tools I offer. Call them with these arguments.” VS Code, a Python script, or a LangChain agent can all be the client on the other side.

Step 3: Creating the 03-DatabaseServer.py

We start with a Database MCP server. I want you to give the model four tools: connect to SQLite, list tables, read a table schema, and run a query.

I have given you a SQLite file named fintech.db. Copy it to C:\database before you continue — every example in this lab points there.

Create a file named 03-DatabaseServer.py in your workspace and paste the code below into it. 

from mcp.server import MCPServer
import sqlite3
from typing import List, Dict, Any, Optional
from pathlib import Path

# Create an MCP server
mcp = MCPServer("DatabaseServer")

@mcp.tool()
def connect_database(db_path: str) -> str:
    """Connect to a SQLite database"""
    try:
        # Ensure the directory exists
        Path(db_path).parent.mkdir(parents=True, exist_ok=True)
        # Test connection
        conn = sqlite3.connect(db_path)
        conn.close()
        return f"Successfully connected to database at {db_path}"
    except Exception as e:
        return f"Error connecting to database: {str(e)}"

@mcp.tool()
def list_tables(db_path: str) -> List[str]:
    """List all tables in the database"""
    try:
        conn = sqlite3.connect(db_path)
        cursor = conn.cursor()
        cursor.execute("SELECT name FROM sqlite_master WHERE type='table';")
        tables = [row[0] for row in cursor.fetchall()]
        conn.close()
        return tables
    except Exception as e:
        return [f"Error listing tables: {str(e)}"]

@mcp.tool()
def get_table_schema(db_path: str, table_name: str) -> str:
    """Get schema information for a specific table as a CREATE TABLE string"""
    try:
        conn = sqlite3.connect(db_path)
        cursor = conn.cursor()
        cursor.execute(
            "SELECT sql FROM sqlite_master WHERE type='table' AND name=?;",
            (table_name,),
        )
        row = cursor.fetchone()
        conn.close()
        if row and row[0]:
            return row[0]
        return f"Table '{table_name}' not found"
    except Exception as e:
        return f"Error getting schema: {str(e)}"

@mcp.tool()
def execute_query(db_path: str, query: str) -> List[Dict[str, Any]]:
    """Execute a SQL query and return results"""
    try:
        conn = sqlite3.connect(db_path)
        conn.row_factory = sqlite3.Row
        cursor = conn.cursor()
        cursor.execute(query)
        results = [dict(row) for row in cursor.fetchall()]
        conn.close()
        return results
    except Exception as e:
        return [{"error": f"Error executing query: {str(e)}"}]

if __name__ == "__main__":
    mcp.run()

Step 6: Creating the 01-FileSystemServer.py

Next I want you to build a File System Server. Same idea as the database server, different tools: list files, read, write, create a directory, delete a file.

Create 01-FileSystemServer.py in the same workspace and paste this in: 

from mcp.server import MCPServer
from pathlib import Path
from typing import List

# Create an MCP server
mcp = MCPServer("FileSystemServer")

@mcp.tool()
def list_files(directory: str) -> List:
    """List all files in a directory"""
    try:
        return [f.absolute() for f in Path(directory).iterdir() if f.is_file()]
    
    except Exception as e:
        return [f"Error: {str(e)}"]

@mcp.tool()
def read_file(file_path: str) -> str:
    """Read contents of a file"""
    try:
        with open(file_path, 'r') as f:
            return f.read()
    except Exception as e:
        return f"Error: {str(e)}"

@mcp.tool()
def write_file(file_path: str, content: str) -> str:
    """Write content to a file"""
    try:
        with open(file_path, 'w') as f:
            f.write(content)
            return f"File written successfully to  {f.name}"
    except Exception as e:
        return f"Error: {str(e)}"

@mcp.tool()
def create_directory(directory: str) -> str:
    """Create a new directory"""
    try:
        Path(directory).mkdir(parents=True, exist_ok=True)
        return "Directory created successfully"
    except Exception as e:
        return f"Error: {str(e)}"

@mcp.tool()
def delete_file(file_path: str) -> str:
    """Delete a file"""
    try:
        Path(file_path).unlink()
        return "File deleted successfully"
    except Exception as e:
        return f"Error: {str(e)}"

if __name__ == "__main__": 
    mcp.run()

Step 7: Creating a Stdio Client for the Database Server

Copilot Chat is one client. You can also write your own. I want you to do that next, so you see exactly how a Python program talks to an MCP server.

Every client in this lab is a single Client object. For stdio, you pass stdio_client(StdioServerParameters(...)) into Client, then enter async with. That opens the connection and negotiates for you. After that you call list_tools() and call_tool(). See Client transports if you want the full list of options.

Save the code below as 04-DatabaseServerClient.py. Run it with mcpvenv still active. 

from mcp import Client, StdioServerParameters
from mcp.client.stdio import stdio_client
import asyncio

# StdioServerParameters is configuration only — always wrap with stdio_client(...)
server_params = StdioServerParameters(
    command="python",  # Executable
    args=["03-DatabaseServer.py"],  # Server script
    env=None,  # Pass API keys here if needed; the child does not inherit your full env
)


async def run():
    # Client takes the transport; async with opens the connection
    async with Client(stdio_client(server_params)) as client:
        # List available tools
        tools = await client.list_tools()
        print("Available tools:", [tool.name for tool in tools.tools])

        db_path = "c:\\database\\fintech.db"

        # call_tool returns CallToolResult — prefer structured_content for application code
        tables = await client.call_tool("list_tables", {"db_path": db_path})
        print("Tables in database:", tables.structured_content)

        schema = await client.call_tool("get_table_schema", {
            "db_path": db_path,
            "table_name": "customers"
        })
        print("Table schema for customers:", schema.structured_content)

        results = await client.call_tool("execute_query", {
            "db_path": db_path,
            "query": "SELECT * FROM customers LIMIT 5"
        })
        print("First 5 customers:", results.structured_content)

if __name__ == "__main__":
    asyncio.run(run())

Run it from the folder where your scripts live, with (mcpvenv) showing in the prompt: 

python 04-DatabaseServerClient.py

This client starts DatabaseServer, connects to fintech.db, lists tables, fetches the schema of customers, and prints the first 5 rows.

In-memory client (no subprocess).
When you are testing, you can skip launching a child process. Pass the server object itself: async with Client(mcp) as client:. Same list_tools / call_tool API — no port, no bytes on a wire.

Step 8: Creating a Database Server with SSE

Stdio is great when the client starts the server as a child process. When the client and server live in different processes (or on different machines), you serve MCP over HTTP instead.

Server-Sent Events (SSE) is one HTTP transport. Later in Step 10 I will show you Streamable HTTP, which is the one I want you to use for new HTTP servers. Learn SSE here so you recognise it if you meet it in the wild.

The constructor describes what the server is. How it is served belongs on mcp.run(...) — that is where transport and port go. Save this as 05-DatabaseServerSSE.py.

Step 11: Creating a Streamable HTTP Client

Pass a URL string to Client and you get Streamable HTTP automatically. You only need streamable_http_client yourself if you want custom headers, auth, or timeouts (then build an httpx2.AsyncClient and wrap it). Save this as 08-DatabaseStreamableHTTPClient.py. 

from mcp import Client
import asyncio


async def run():
    # A URL string uses Streamable HTTP
    async with Client("http://localhost:8000/mcp") as client:
        tools = await client.list_tools()
        print(f"Available tools: {[tool.name for tool in tools.tools]}")

        db_path = "c:\\database\\fintech.db"

        tables = await client.call_tool("list_tables", {"db_path": db_path})
        print("Tables in database:", tables.structured_content)

        schema = await client.call_tool("get_table_schema", {
            "db_path": db_path,
            "table_name": "customers"
        })
        print("Table schema for customers:", schema.structured_content)

        results = await client.call_tool("execute_query", {
            "db_path": db_path,
            "query": "SELECT * FROM customers LIMIT 5"
        })
        print("First 5 customers:", results.structured_content)


if __name__ == "__main__":
    asyncio.run(run())
Custom HTTP client (auth / headers / timeouts). Build your own httpx2.AsyncClient and pass it to streamable_http_client(url, http_client=...), then Client(transport). Headers, timeouts, and redirects all live on the httpx client. 
import httpx2
from mcp import Client
from mcp.client.streamable_http import streamable_http_client
import asyncio


async def run():
    async with httpx2.AsyncClient(
        headers={"Authorization": "Bearer ..."},
        timeout=httpx2.Timeout(30.0, read=300.0),
        follow_redirects=True,
    ) as http_client:
        transport = streamable_http_client(
            "http://localhost:8000/mcp",
            http_client=http_client,
        )
        async with Client(transport) as client:
            tools = await client.list_tools()
            print([tool.name for tool in tools.tools])


if __name__ == "__main__":
    asyncio.run(run())

from langchain_mcp_adapters.client import MultiServerMCPClient
from langchain.agents import create_agent
import asyncio
import os

# Ensure you have OPENAI_API_KEY set in your environment
# os.environ["OPENAI_API_KEY"] = "your-api-key-here"


async def main():
    # Create a MultiServerMCPClient with the Database Server
    client = MultiServerMCPClient(
        {
            "database": {
                "transport": "stdio",  # Local subprocess communication
                # Must be mcpvenv Python so the server runs with the current MCP SDK
                "command": r"C:\path\to\your\workspace\mcpvenv\Scripts\python.exe",
                # Update with the absolute path to your DatabaseServer script
                "args": ["C:\\path\\to\\your\\workspace\\03-DatabaseServer.py"],
            }
        }
    )

    # Get tools from the MCP server
    tools = await client.get_tools()
    print(f"Available tools: {[tool.name for tool in tools]}")

    # Create a LangChain agent using create_agent with gpt-4o-mini
    agent = create_agent(
        "openai:gpt-4o-mini",  # Model specification
        tools  # MCP tools
    )

    # Example query: list all tables
    print("\n" + "="*80)
    print("List all tables in the fintech database")
    print("="*80)
    result = await agent.ainvoke({
        "messages": [{"role": "user", "content": "List all tables in the database located at c:\\database\\fintech.db"}]
    })
    print(f"\nResult: {result['messages'][-1].content}\n")


if __name__ == "__main__":
    asyncio.run(main())

Step 13: Using Multiple MCP Servers with LangChain

Stay in the old course venv for this LangChain client. One agent can talk to more than one MCP server. MultiServerMCPClient collects tools from all of them, so the same agent can query the database and write a file.

The example below connects to FileSystemServer (stdio, launched with mcpvenv Python) and DatabaseServerStreamable (Streamable HTTP — you start that server yourself in mcpvenv). Save it as 10-LangChainMultiServerAgent.py. 

from langchain_mcp_adapters.client import MultiServerMCPClient
from langchain.agents import create_agent
import asyncio
import os

# Ensure you have OPENAI_API_KEY set in your environment
# os.environ["OPENAI_API_KEY"] = "your-api-key-here"


async def main():
    # Create a MultiServerMCPClient with both FileSystem and Database servers
    client = MultiServerMCPClient(
        {
            "filesystem": {
                "transport": "stdio",  # Local subprocess communication
                # Must be mcpvenv Python so the server runs with the current MCP SDK
                "command": r"C:\path\to\your\workspace\mcpvenv\Scripts\python.exe",
                # Update with the absolute path to your FileSystemServer script
                "args": ["C:\\path\\to\\your\\workspace\\01-FileSystemServer.py"],
            },
            "database": {
                "transport": "http",  # Streamable HTTP transport
                # Make sure DatabaseServerStreamableHTTP is running on port 8000
                "url": "http://localhost:8000/mcp",
            }
        }
    )

    # Get tools from all MCP servers
    tools = await client.get_tools()
    print(f"Available tools: {[tool.name for tool in tools]}")

    # Create a LangChain agent using create_agent with gpt-4o-mini
    agent = create_agent(
        "openai:gpt-4o-mini",  # Model specification
        tools  # Combined MCP tools from multiple servers
    )

    # Example: Query database and save results to a file
    print("\n" + "="*80)
    print("Multi-Server Task: Query database and save results to file")
    print("="*80)
    result = await agent.ainvoke({

Step 14: Using the Official GitHub MCP Server with LangChain

Stay in the old course venv for this LangChain client as well. You do not have to write every MCP server yourself. The ecosystem already has servers in TypeScript, Go, Rust, and more. In this last step I want you to connect to an existing open-source server and give its tools to a LangChain agent.

We will use @modelcontextprotocol/server-github — the official GitHub MCP server from the Model Context Protocol project. It talks to the GitHub REST API and exposes tools for searching repositories, reading files, listing issues and pull requests, and more. You will not run local git commands.

Part A — Install Node.js (required for the GitHub MCP server)

This GitHub server is an npm package, so you need Node.js (v18 or later) on your machine.

  1. Open nodejs.org in your browser and download the LTS installer for Windows.
  2. Run the installer and accept all defaults — make sure "Add to PATH" is ticked.
  3. Open a new terminal and verify the installation:
node --version   # should print v18.x or higher
npx --version    # bundled with Node — prints a version number
What is npx?
npx ships with Node.js. It runs an npm package on demand without installing it globally. The -y flag skips the confirmation prompt, which you need when Python launches the MCP server for you.

Part B — Set Up the GitHub MCP Server

The GitHub MCP server talks to the GitHub REST API. You need a Personal Access Token (PAT) so GitHub knows who is calling.

Part B1 — Create a GitHub Personal Access Token

For the read-only demos in this step (search repos, read files, list issues), a token that can read public repositories is enough:

  1. Sign in to github.com.
  2. Click your profile picture (top‑right corner) and choose Settings.
  3. Scroll to the very bottom of the left sidebar and click Developer settings.
  4. In the left sidebar click Personal access tokens → Tokens (classic).
  5. Click Generate new token → Generate new token (classic).
  6. Fill in the form:
    • Note: give it a recognisable name, e.g. mcp-github-demo.
    • Expiration: choose 90 days (or longer for class use).
    • Scopes — tick the following for this lab:
      • public_repo — read (and optionally write) public repositories.
      • read:user — read your GitHub profile (useful for repo searches scoped to your account).
      If you also want to query private repos, tick the top-level repo scope instead.
  7. Click Generate token at the bottom of the page.
  8. Copy the token immediately. GitHub shows it only once. It starts with ghp_ followed by a long random string.
Keep your token secret. Never commit it to a repository or paste it into a shared file. Treat a PAT the way you treat a password.

Part B2 — Set the Token as an Environment Variable

Set the token in your terminal before you run any script in this step. Replace ghp_xxxx with your actual token: 

# Windows Command Prompt
set GITHUB_PERSONAL_ACCESS_TOKEN=ghp_xxxx

# Windows PowerShell
$env:GITHUB_PERSONAL_ACCESS_TOKEN="ghp_xxxx"

To make it permanent (so you do not have to set it every session), add it to Windows user environment variables:

  1. Press Win + S and search for Edit the system environment variables.
  2. Click Environment Variables…
  3. Under User variables, click New.
  4. Variable name: GITHUB_PERSONAL_ACCESS_TOKEN  |  Variable value: your token.
  5. Click OK on all dialogs, then open a fresh terminal.

Part B3 — Verify the GitHub Server Starts (Optional Smoke Test)

Run the server manually once to confirm the npm package downloads and your token is accepted: 

npx -y @modelcontextprotocol/server-github

The server starts and waits for MCP messages on stdin. If you see no error, the package and token are working. Press Ctrl+C to stop.

Part C — GitHub MCP Tools Overview

The server exposes tools that map to GitHub REST API operations. For this lab, stay with the read-oriented ones. You will call them in natural language:

  • search_repositories — search repos by keyword, language, stars, owner, etc.
  • get_file_contents — read a file or list a directory in a repo.
  • list_issues — list open or closed issues in a repository.
  • list_pull_requests — list pull requests in a repository.
  • list_commits — list recent commits on a branch.
  • search_code, search_issues, search_users — GitHub search syntax.

The same package also includes write tools (create_issue, create_pull_request, fork_repository, and others) if you want to extend the exercises later. All of them go through the GitHub API. You still do not need a local git server.

This is an official, maintained server.
Development continues in github/github-mcp-server. I use the npm package @modelcontextprotocol/server-github in this lab because npx launches it in one line, which matches how most MCP servers are started.

Part D — GitHub Demo Agent — 11-GitHubAgent.py

Save the script below as 11-GitHubAgent.py. It connects LangChain to the GitHub MCP server and runs four demos: search repositories, read a README, list open issues, and list open pull requests. 

import asyncio
import os
from pathlib import Path

from dotenv import load_dotenv
from langchain_mcp_adapters.client import MultiServerMCPClient
from langchain.agents import create_agent

load_dotenv(Path(__file__).parent / ".env")

DEMOS = [
    (
        "Search repositories",
        "Search GitHub for Python repositories related to langchain with more than 5000 stars. "
        "Show the top 5 matches with repository name, description, and star count.",
    ),
    (
        "Read a README",
        "Show the contents of README.md from the langchain-ai/langchain repository on the main branch. "
        "Summarize the first few paragraphs.",
    ),
    (
        "List open issues",
        "List the 5 most recently updated open issues in octocat/Hello-World. "
        "Show issue number, title, and state for each.",
    ),
    (
        "List open pull requests",
        "List up to 5 open pull requests in microsoft/vscode. "
        "Show the PR number, title, and author for each.",
    ),
]


async def main():
    github_token = os.environ.get("GITHUB_PERSONAL_ACCESS_TOKEN", "")
    if not github_token:
        raise EnvironmentError(
            "GITHUB_PERSONAL_ACCESS_TOKEN is not set.\n"
            "Run:  set GITHUB_PERSONAL_ACCESS_TOKEN=ghp_xxxx"
        )

    client = MultiServerMCPClient(
        {
            "github": {
                "transport": "stdio",
                "command": "npx",
                "args": ["-y", "@modelcontextprotocol/server-github"],
                "env": {
                    **os.environ,
                    "GITHUB_PERSONAL_ACCESS_TOKEN": github_token,
                },
            },
        }
    )

    tools = await client.get_tools(server_name="github")
    print(f"GitHub MCP tools loaded ({len(tools)}): {[t.name for t in tools]}\n")

    agent = create_agent("openai:gpt-4o-mini", tools)

    for title, prompt in DEMOS:
        print("=" * 70)
        print(title)
        print("=" * 70)
        result = await agent.ainvoke(
            {"messages": [{"role": "user", "content": prompt}]}
        )
        print(result["messages"][-1].content)
        print()


if __name__ == "__main__":
    asyncio.run(main())

Part F — Optional: Register with VS Code

You can also use the GitHub MCP server in Copilot Chat without writing Python. Add this entry to .vscode/mcp.json. VS Code will ask for your token the first time you start it: 

{
  "inputs": [
    {
      "type": "promptString",
      "id": "github-token",
      "description": "GitHub Personal Access Token",
      "password": true
    }
  ],
  "servers": {
    "github": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${input:github-token}"
      }
    }
  }
}

Save, click Start on the server in mcp.json, open Copilot Chat in Agent mode, and try prompts such as “Search GitHub for MCP server repositories” or “List open issues in octocat/Hello-World”.
